Deutsch's algorithm: your first quantum speedup

A black box hides a one-bit function. Is it constant or balanced? A classical computer must ask the box twice. A quantum computer asks once, and the reason is not "trying both inputs at once": it is making the wrong answer cancel out.

From class Week 2, Sat 24 Oct 2026, afternoon lecture. Uses only H, X, Z and CNOT, so read gates and entanglement first.

Back to basics: XOR, and the four one-bit functions

A function f from {0, 1} to {0, 1} takes one bit and gives one bit. There are only four of them, because you choose f(0) (2 ways) and f(1) (2 ways): 2 × 2 = 4.

Namef(0)f(1)Type
always 000constant
always 111constant
copy (f(x) = x)01balanced
flip (f(x) = 1 − x)10balanced

Constant = both outputs the same. Balanced = one 0 and one 1. A neat test: f is constant exactly when f(0) ⊕ f(1) = 0.

Tiny example: is "flip" constant? f(0) ⊕ f(1) = 1 ⊕ 0 = 1, so no: balanced.

XOR table y ⊕ b 0 ⊕ 0 = 0 (no flip) 0 ⊕ 1 = 1 (flip) 1 ⊕ 0 = 1 (no flip) 1 ⊕ 1 = 0 (flip) "y ⊕ b" = "flip y if b is 1" ✓

The idea

A dealer hands you a coin. A fair coin has two different faces; a trick coin has the same face twice. You may look at one side at a time, each look costs money, and you must be 100% sure. One look shows "heads", which fits both coins, so you need two looks. Note what you are really asking: not "what are the faces?" but "are they the same or different?", a question about the coin as a whole.

The black box ("oracle") is that coin: feed in x, read out f(x), never open it. Classically you need 2 queries. Ask f(0) and get 0: "always 0" and "copy" are both still possible, and only f(1) can separate them.

Deutsch's algorithm needs 1 query, in three moves: make the box reversible, park a helper qubit at |−⟩ so the answer becomes a phase on the input ("kickback"), then use H to turn that phase into a 0 or 1 you can read ("interference").

Move 1: make the box reversible

Quantum gates are rotations, and every rotation can be undone. "Output f(x)" can't be: if "always 0" outputs 0, you can't tell whether the input was 0 or 1. The fix is to keep the input and write the answer on a second "helper" wire:

|x⟩|y⟩ ↦ |x⟩|y ⊕ f(x)⟩

Read it aloud: "ket x, ket y maps to ket x, ket y x-or f of x". In words: look at x; if f(x) = 1, flip the helper; otherwise do nothing. Run it twice and the helper is flipped twice, back where it started: reversible. (Class states this formula properly in the third lecture.)

BoxCircuit insideWhy
always 0nothingnever flip
always 1X on the helperalways flip
copyCNOT, input → helperflip if x = 1
flipX on input, CNOT, X on inputflip if x = 0

Constant boxes never touch the input wire. Balanced boxes need the CNOT, because the helper's fate depends on x. A real box could be millions of gates; only its behaviour matters.

Move 2 (a dead end): quantum parallelism

Feed the input wire |+⟩ (the equator) and the helper |0⟩. One pass through the box acts on both "lanes", x = 0 and x = 1, at once:

|+⟩|0⟩ = (|0⟩|0⟩ + |1⟩|0⟩)/√2 —U_f→ (|0⟩|f(0)⟩ + |1⟩|f(1)⟩)/√2

Both answers are "in the state". For the copy box this is (|00⟩ + |11⟩)/√2, the Bell pair from the morning. The catch: measuring casts one shadow. You get one lane at random and learn one value of f: worse than a classical query, since you didn't even choose which input.

Parallelism alone is useless. The lanes have to interfere, so that the relationship between f(0) and f(1) shows up in one readout.

Move 3: phase kickback

Class poll. Control at |+⟩, target at |−⟩. Apply CNOT. Which Bloch arrow moves? A) target B) control C) both D) neither.

Answer: B, the control. CNOT "flips the target", yet the target stays put and the control turns from |+⟩ to |−⟩. Why, in four steps:

  1. The control |+⟩ is a 0-branch and a 1-branch side by side.
  2. CNOT acts only on the 1-branch: it applies X to the target there.
  3. The target |−⟩ lies on the x-axis, so a half-turn about x can't move it. It only leaves a minus sign: X|−⟩ = −|−⟩.
  4. That minus sign sits on the control's 1-branch. A minus on the 1-branch is exactly a Z: |+⟩ → |−⟩.
CNOT (|+⟩|−⟩) = CNOT (|0⟩|−⟩ + |1⟩|−⟩)/√2 = (|0⟩|−⟩ + |1⟩ X|−⟩)/√2 = (|0⟩|−⟩ − |1⟩|−⟩)/√2 = (|0⟩ − |1⟩)/√2 ⊗ |−⟩ = |−⟩|−⟩ ✓ the control moved

The same works for any box: with the helper parked at |−⟩, "flip the helper if f(x) = 1" becomes "put a minus sign on |x⟩ if f(x) = 1":

U_f |x⟩|−⟩ = (−1)^f(x) |x⟩|−⟩

Read it aloud: "U f on ket x ket minus equals minus one to the f of x, times ket x ket minus". The helper is an anchor; the kick travels back up the input wire.

BoxInput wire feelsInput |+⟩ ends at

Constant ⇒ east. Balanced ⇒ west. The answer is now the input qubit's longitude. We just need to read longitude, and H turns longitude into latitude.

Deutsch's circuit

Constant box
|0⟩ —H→ |+⟩ (east) —U_f→ |+⟩ (no twist) —H→ |0⟩ (north) reads 0, every time
Balanced box
|0⟩ —H→ |+⟩ (east) —U_f→ |−⟩ (kicked west) —H→ |1⟩ (south) reads 1, every time
It's the morning's poll! Constant box: the input sees H H, which reads 0. Balanced box: it sees H Z H, which reads 1. Deutsch's algorithm in one sentence: the oracle secretly decides whether a Z sits between two Hadamards, and the answer comes out with certainty after one query.

Class poll. In "always 1" the helper is flipped. Why does the readout still say 0? A) Quirk bug B) the flip only adds an overall sign C) the final H undoes it. Answer B: a constant box treats both lanes the same, so the sign hits both lanes equally and nothing relative changes.

Why it works: adding arrows (Feynman's picture)

Each H is a fork in the road. From the start, the input goes to lane 0 or lane 1, then the second H sends each lane to readout 0 or 1: four routes. Each route carries a little arrow (an amplitude): the two H-amplitudes along it multiplied, here (1/√2)(1/√2) = ½, except the route lane 1 → 1, which is (1/√2)(−1/√2) = −½. A balanced box also reverses every route through lane 1. The rule: add the arrows of all routes to an ending; the chance is the length of the total, squared.

RouteConstantBalanced
lane 0 → 0+½+½
lane 1 → 0+½−½
lane 0 → 1+½+½
lane 1 → 1−½+½
reach 0½ + ½ = 1½ − ½ = 0
reach 1½ − ½ = 0½ + ½ = 1

The −½ in "lane 1 → 1" comes from the second H: H|1⟩ = |−⟩ has a minus on |1⟩. The kick reverses every route through lane 1, so the cancellation swaps from "1" to "0".

The speedup is engineered cancellation. Three ingredients: spread (H opens many routes), mark (the oracle kicks signs onto some routes), interfere (H recombines them, and the signs decide what survives). Bernstein–Vazirani, Simon, Grover and Shor all follow this pattern.

Key definition

constant ⇔ f(0) ⊕ f(1) = 0

Read it aloud: "f is constant if and only if f of zero x-or f of one is zero". Deutsch's circuit reads 0 exactly in that case. Deutsch's circuit measures f(0) ⊕ f(1), a fact about the whole function, with one query, and never learns f(0) or f(1) themselves.

Worked example, every step shown: the "copy" box

Start |0⟩|0⟩ X on helper |0⟩|1⟩ H on both |+⟩|−⟩ = (|0⟩ + |1⟩)/√2 ⊗ |−⟩ Oracle (CNOT) lane 0: f(0) = 0, sign (−1)⁰ = +1 lane 1: f(1) = 1, sign (−1)¹ = −1 → (|0⟩ − |1⟩)/√2 ⊗ |−⟩ = |−⟩|−⟩ H on input H|−⟩ = |1⟩ → |1⟩|−⟩ Measure input P(1) = 1 Result 1 ⇒ balanced ✓

Do the same for "always 1" yourself: both lanes get sign −1, so the input is −|+⟩, a global sign. H gives −|0⟩, which reads 0 with probability |−1|² = 1: constant.

From 1 bit to n bits: Deutsch–Jozsa

Now f takes an n-bit input. The promise: f is either constant, or balanced (exactly half its 2ⁿ outputs are 1). Same recipe: n input wires all |0⟩ with an H on each, the helper at |−⟩, one query, H on every input wire again. Readout rule: all inputs read 0 ⇒ constant; anything else ⇒ balanced.

Same picture with 2ⁿ routes. For a constant box, every route to "all zeros" carries the same arrow, so they all add up. For a balanced box exactly half are flipped, and they cancel completely. (The algebra comes in the third lecture.)

Common mistakes

  • "It tries both inputs at once and reads both answers." No: measurement gives one lane at random. The win comes from interference, not from reading everything.
  • Forgetting the helper's X. Without it the helper sits at |+⟩, X|+⟩ = +|+⟩, nothing kicks back, and every box reads 0 (sandbox task 3 below).
  • Expecting the helper to move. In kickback the target stays put; the control (input) changes.
  • Treating a global sign as an answer. "Always 1" makes the whole state −1 times itself. That is invisible.
  • Reading Qiskit counts left to right. Qiskit lists bits right to left, so a count "q1q0" has qubit 0 on the right.

Practice: the class sandbox

In class the sandbox had Deutsch's circuit with an empty slot and three mystery boxes A, B, C (the links were shared in the class chat). Task 1: drop each box in, run once, decide constant or balanced. The two thinking tasks work without the boxes:

Task 2: one of the balanced boxes contains no CNOT. How can it still be balanced?

Balanced only means "flips the helper for exactly one of x = 0, 1". The box's insides can be anything that behaves that way. Two common ways without a CNOT gate:

  • A controlled-Z between two H's on the helper: H·CZ·H on the target is exactly a CNOT, built from other parts.
  • A Z straight on the input wire: with the helper at |−⟩, a CNOT's only effect is a Z on the input (kickback). A box that just applies Z to the input gives the same readout, 1. It skips the "flip the helper" story and goes straight to the phase.

Open your box in Quirk to see which one it uses. The lesson: the algorithm only ever sees the phase the box leaves on the input.

Task 3 (stretch): remove the helper's X gate, so it starts at |+⟩ instead of |−⟩. What breaks, and why?

Run it in Qiskit

from qiskit import QuantumCircuit
qc = QuantumCircuit(2, 1)
qc.x(1)            # helper to |1>
qc.h([0, 1])       # spread; helper to |->
qc.cx(0, 1)        # oracle: "copy"
qc.h(0)            # interfere
qc.measure(0, 0)   # read the input

Qubit 0 is the input, qubit 1 the helper. Run 1000 shots: you should see one outcome every time (here, 1). Swap the oracle line to try the others: delete it for "always 0", qc.x(1) for "always 1", and qc.x(0); qc.cx(0, 1); qc.x(0) for "flip".
